# URL Shortener

## 1. Доменная область приложения

Приложение относится к доменной области **управления ссылками (URL management / link shortening)**.

Назначение: сокращение длинных URL в короткие коды для удобного распространения, хранения и последующего перенаправления пользователей на исходный адрес.

Основные бизнес-процессы:

1. Создание короткой ссылки двумя способами:
   - автоматическая генерация случайного кода (Base62, длина 6 символов);
   - создание ссылки с пользовательским (кастомным) кодом по шаблону `[a-zA-Z0-9_-]{5,10}`.
2. Модерация кастомного кода: перед сохранением `url-service` синхронно обращается в `moderation-service` (`POST /shortcode`) и отклоняет коды, содержащие запрещённые подстроки.
3. Хранение соответствия `shortCode <-> longUrl` с аудитом времени создания/изменения.
4. Получение ссылки по `id`, листинг всех ссылок, обновление `longUrl`, удаление ссылки.
5. Перенаправление: `GET /{shortCode} -> 302 Found` с заголовком `Location: <longUrl>`.

Архитектура: два микросервиса + PostgreSQL + one-shot Liquibase-мигратор, оркестрация через `docker-compose.yaml`:

- `url-service` (порт `URL_SERVICE_PORT`, по умолчанию `8080`) — основной CRUD и редирект;
- `moderation-service` (порт `MODERATION_SERVICE_PORT`, по умолчанию `8081`, внутри сети `http://moderation-service:8081`) — проверка кода;
- `url-postgres` (`postgres:16`) — персистентное хранилище;
- `url-liquibase` (`liquibase/liquibase:4.29`) — накат схемы из `url-service/migrations/changelog/changelog.xml`.

## 2. Стек реализации

- **Язык и платформа:** Java 25, Maven 3.9 (multi-module проект, parent `spring-boot-starter-parent:4.1.1`).
- **Фреймворк:** Spring Boot 4.1.1:
  - `spring-boot-starter-web` (REST-контроллеры обоих сервисов);
  - `spring-boot-starter-data-jpa` + Hibernate (`ddl-auto: validate`) — только в `url-service`;
  - `spring-boot-starter-validation` (валидация DTO и `@ConfigurationProperties`);
  - `spring-boot-starter-test`, `spring-boot-starter-webmvc-test` (тесты);
  - `spring-boot-liquibase` (в test-scope `url-service`), Testcontainers (`postgresql`, `testcontainers`, `spring-boot-testcontainers`) для интеграционных тестов.
- **Маппинг и бойлерплейт:** MapStruct 1.6.3 (`UrlMapper`), Lombok 1.18.46 (+ `lombok-mapstruct-binding:0.2.0`).
- **БД и миграции:** PostgreSQL 16 + драйвер `postgresql:42.7.13`, Liquibase 4.29 (отдельный контейнер, SQL-файлы `create-url-table.sql`, `create-url-index.sql`).
- **Конфигурация:** YAML (`application.yaml` в каждом сервисе) + переменные окружения из корневого `.env` (`POSTGRES_DB/USER/PASSWORD/PORT/HOST`, `URL_SERVICE_PORT/HOST`, `MODERATION_SERVICE_PORT/HOST`).
- **Сборка и запуск:** Multi-stage `Dockerfile` в каждом сервисе (`maven:3.9-eclipse-temurin-25` -> `eclipse-temurin:25-jre-alpine`, `mvn clean package -DskipTests`, `java -jar app.jar`), публикация образов `mkhalez/url-service:latest` и `mkhalez/moderation-service:latest`, запуск `docker compose up -d`.
- **Взаимодействие сервисов:** HTTP/REST + JSON; `url-service` хранит `moderation-client.base-url`, `connection-timeout: 3000`, `read-timeout: 3000`.

## 3. Основные сущности доменной области приложения

Единственная персистентная доменная сущность — `UrlEntity` (таблица `url`, `url-service/src/main/java/.../domain/entities/UrlEntity.java`):

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `Integer`, `@Id @GeneratedValue(IDENTITY)` | Суррогатный первичный ключ, используется в CRUD `GET/PUT/DELETE /urls/{id}` |
| `shortCode` | `String` | Короткий код (уникальный бизнес-ключ, индекс `create-url-index.sql`), используется в редиректе `GET /{shortCode}` |
| `longUrl` | `String` | Исходный длинный URL — цель редиректа |
| `createdAt` | `LocalDateTime`, `@CreatedDate`, колонка `created_at NOT NULL` | Аудит создания (JPA Auditing) |
| `lastModifiedAt` | `LocalDateTime`, `@LastModifiedDate`, колонка `last_modified_at NOT NULL` | Аудит последнего изменения |

Вспомогательные (не персистентные) модели:

- DTO `url-service`: `CreateRandomUrlRequest{longUrl}`, `CreateCustomUrlRequest{longUrl, customShortCode}`, `UpdateUrlRequest{longUrl}`, `UrlResponse{id, longUrl, shortUrl}`, `CheckShortCodeRequest{shortCode}`, `CheckShortCodeResponse{shortCode, status}`, enum `ShortCodeCheckStatus{VALID, NOT_VALID}`.
- DTO `moderation-service`: `CheckShortCodeRequest{shortCode}`, `CheckShortCodeResponse{shortCode, status}`, enum `ShortCodeCheckStatus{VALID, NOT_VALID}`; конфигурационный record `BannedWordsProperties(Set<String> bannedWords)` (по умолчанию `spamm, slopp, booot`, сравнение case-insensitive через `contains` в `ShortCodeCheckerImpl`).
- Репозиторий `UrlRepository` (JPA): `findByLongUrl`, `findByShortCode`, `existsByShortCode`.
- Конфигурационные properties: `UrlProperties(url.short-url-length=6, url.host)`, `ModerationClientProperties(moderation-client.base-url, connection-timeout, read-timeout)`.

`moderation-service` сущностей БД не имеет — stateless-сервис проверки.

## 4. Соответствие методологии 12 факторов (12-Factor App)

### I. Codebase — Одна кодовая база под версионным контролем, много развёртываний

Один Git-репозиторий, один корневой `pom.xml` (packaging `pom`, модули `url-service`, `moderation-service`), общие `docker-compose.yaml`, `.env`, `README.md`. Оба сервиса собираются из этой кодовой базы (`Dockerfile` копируют свой `pom.xml` + `src` и выполняют `mvn clean package`). Развёртывание — сборка образов `mkhalez/url-service:latest`, `mkhalez/moderation-service:latest` и запуск через Compose.

### II. Dependencies — Явное объявление и изоляция зависимостей

Все зависимости явно объявлены в `pom.xml` (корневой + по одному на сервис): Spring Boot starters, Lombok, MapStruct, PostgreSQL-драйвер, Testcontainers (test-scope). Изоляция — сборка в Maven-контейнере (`mvn dependency:go-offline`, multi-stage `Dockerfile`), runtime-контейнер содержит только JRE + `app.jar`. Системных/глобальных зависимостей не требуется, кроме Docker/Java для сборки.

### III. Config — Конфигурация в окружении

Никаких захардкоженных хостов/паролей в коде: `application.yaml` использует подстановки `${URL_SERVICE_PORT}`, `${POSTGRES_HOST}`, `${POSTGRES_PORT}`, `${POSTGRES_DB}`, `${POSTGRES_USER}`, `${POSTGRES_PASSWORD}`, `${MODERATION_SERVICE_HOST}`, `${MODERATION_SERVICE_PORT}`; `url.host`, `moderation-client.base-url` собираются из env. Значения поставляются через корневой `.env` и `environment:` в `docker-compose.yaml` без пересборки образов.

### IV. Backing services — Подключаемые ресурсы как внешние сервисы

PostgreSQL трактуется как attached resource: URL/credentials передаются через env (`spring.datasource.url=jdbc:postgresql://${POSTGRES_HOST}:${POSTGRES_PORT}/${POSTGRES_DB}`), замена БД — сменой переменных без изменения кода. Аналогично `moderation-service` для `url-service` — внешний HTTP-ресурс, адрес задаётся `moderation-client.base-url` (в Compose — `http://moderation-service:8081`). Healthcheck `pg_isready` и `depends_on: service_healthy` подчёркивают взаимозаменяемость ресурса.

### V. Build, release, run — Строгое разделение стадий сборки, релиза и выполнения

Разделение есть: build — `mvn clean package` в builder-стадии `Dockerfile`; release — комбинация готового образа + `docker-compose.yaml` + `.env` + накат Liquibase-миграций (`url-liquibase: update`); run — `java -jar app.jar` в runtime-контейнере с `restart: unless-stopped`. Нарушение строгости: образы публикуются/используются под мутабельным тегом `latest` без неизменяемого ID релиза (git-sha/ semver), поэтому релиз не является строго идентифицируемым и воспроизводимым.

### VI. Processes — Приложение как stateless-процессы

Оба сервиса stateless: состояние хранится только в PostgreSQL (`url-service`) либо отсутствует вовсе (`moderation-service` хранит лишь in-memory `Set<String> bannedWords`). Ничего не хранится в локальной файловой системе контейнера или sticky-сессиях, поэтому процессы взаимозаменяемы.

### VII. Port binding — Экспорт сервисов через привязку портов

Каждый сервис — самодостаточный HTTP-сервер (встроенный Tomcat): `server.port: ${URL_SERVICE_PORT}` и `${MODERATION_SERVICE_PORT}`, порты публикуются через `ports: ["${URL_SERVICE_PORT}:${URL_SERVICE_PORT}"]` и внутреннюю сеть `backend`. Внешний веб-сервер (nginx/apache) не требуется; межсервисное взаимодействие — тоже по URL `http://moderation-service:8081`.

### VIII. Concurrency — Масштабирование через модель процессов

Благодаря stateless (фактор VI) сервисы *способны* масштабироваться горизонтально (реплики), а Spring Boot обрабатывает запросы конкурентно.
### IX. Disposability — Быстрый запуск и graceful shutdown

Контейнеры запускаются быстро (`eclipse-temurin:25-jre-alpine` + один `app.jar`), есть `healthcheck` Postgres, упорядоченный старт через `depends_on` (`service_healthy`, `service_completed_successfully`), `restart: unless-stopped` перезапускает упавшие процессы. Но явный graceful shutdown не настроен (нет `stop_grace_period`, `preStop`-хуков, обработки `SIGTERM` в коде — полагаемся на дефолт Spring/JVM), поэтому корректное завершение in-flight запросов не гарантировано.

### X. Dev/prod parity — Паритет разработки, staging и production

Разрыв минимизирован: везде один и тот же PostgreSQL 16 (Docker-образ и в prod-Compose, и в Testcontainers-интеграционных тестах `UrlServiceIntegrationTests`), миграции — один и тот же `changelog.xml` через Liquibase, backend-зависимости поднимаются тем же `docker-compose.yaml`, различия только в значениях env. Сборка зависимостей фиксируется версиями в `pom.xml` (Spring Boot 4.1.1, драйвер 42.7.13, Testcontainers 1.21.4/2.0.5).

### XI. Logs — Логи как поток событий

Приложение пишет логи в stdout/stderr (стандартный вывод Spring Boot, `jpa.show-sql: true`, `format_sql: true`) и не управляет файлами логов — это правильно по фактору.

### XII. Admin processes — Административные задачи как one-off процессы

Миграции схемы вынесены в one-off процесс `url-liquibase` (`command: ["update"]`, volume `./url-service/migrations:/liquibase/changelog`, `changelog/changelog.xml` -> `create-url-table.sql`, `create-url-index.sql`), который выполняется однократно до старта `url-service`.
